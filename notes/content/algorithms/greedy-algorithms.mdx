## Purpose

A greedy algorithm builds its answer one irrevocable choice at a time, always taking whatever looks best right now. That is easy to code and often wrong, so every greedy algorithm needs a proof. This note works through the two interval problems where the right greedy choice can be proved optimal:

| Problem | Goal | Greedy order | Why it is optimal |
| --- | --- | --- | --- |
| Interval scheduling | Keep the most pairwise-disjoint intervals | Earliest finish time | Greedy stays ahead: its $r$th interval ends no later than the $r$th interval of any optimal answer |
| Interval partitioning | Put every interval in a room, using the fewest rooms | Earliest start time | When greedy opens room $d$, it can point at $d$ intervals that all overlap one moment, so every answer needs $d$ rooms |

Most of the interest is in the orders that look just as reasonable and lose. The figure below runs each one on an input you can edit, next to an optimum found by brute force. An experiment then measures how often and by how much they lose on random inputs. The last sections cover why greedy fails once intervals carry weights, and what changes when they arrive online.

The proofs use induction; [[algorithms/induction|Induction]] covers the pattern. Intervals are half-open, $[s(j), f(j))$, so one can start exactly when another finishes.

## Interval Scheduling

Job $j$ runs from $s(j)$ to $f(j)$, and two jobs are compatible if they don't overlap. The goal is to keep as many jobs as possible with no two overlapping. It is the first of the two classic [[reference/cheatsheets/algorithms/intervals|interval problems]].

Every rule in this note uses the same template. Sort the jobs by some key, scan them in that order, and keep each job that is compatible with everything kept so far. Only the key changes. [Kleinberg and Tardos (§4.1)](https://www.cs.princeton.edu/~wayne/kleinberg-tardos/pdf/04GreedyAlgorithmsI.pdf) list four natural keys:

| Rule | Keeps next | Smallest input where it loses |
| --- | --- | --- |
| Earliest start | the job that starts first | $[0, 3), [1, 2), [2, 3)$: keeps $[0, 3)$ alone, while $[1, 2), [2, 3)$ gives 2 |
| Shortest first | the shortest job | $[0, 3), [2, 4), [3, 5)$: keeps $[2, 4)$ alone, while $[0, 3), [3, 5)$ gives 2 |
| Fewest conflicts | the job that overlaps the fewest others | $[0, 1), [0, 2), [0, 2), [1, 4), [3, 5), [4, 7), [5, 8), [7, 8)$: keeps 3, while earliest finish keeps 4. No input of 7 or fewer intervals with small integer endpoints loses |
| Earliest finish | the job that finishes first | none |

The first two are the smallest possible: an exhaustive search over inputs with integer endpoints found nothing smaller. Fewest conflicts rarely loses on small inputs, so its example came from a random search that deletes intervals while the rule still loses; the [measurement record](#how-badly-the-wrong-rules-lose) has the details.

With earliest finish the template gets simpler. Kept jobs come out sorted by finish time, so a new job is compatible with all of them exactly when it starts after the last one ends:

```python
def interval_scheduling(jobs):
    """jobs: list of (start, finish). Returns a largest set of disjoint jobs."""
    last = float("-inf")
    selected = []
    for s, f in sorted(jobs, key=lambda job: job[1]):
        if s >= last:
            selected.append((s, f))
            last = f
    return selected
```

The sort costs $O(n \log n)$ and the scan $O(n)$. Sorting can't be avoided in general: [Bhattacharya et al. (2014, Lemma 2)](https://www.cccg.ca/proceedings/2014/papers/paper33.pdf) reduce element uniqueness to this problem, and combined with Ben-Or's $\Omega(n \log n)$ bound for element uniqueness in the algebraic decision tree model, that gives the same lower bound here.

### Why earliest finish is optimal: greedy stays ahead

Say greedy kept jobs $i_1, \ldots, i_k$ and some optimal answer keeps $j_1, \ldots, j_m$, both listed in order of finish time. The goal is $m \le k$.

**Lemma.** $f(i_r) \le f(j_r)$ for every $r \le k$.

**Proof** by induction on $r$. For $r = 1$, greedy's first pick finishes earliest of all jobs. For the step, assume $f(i_{r-1}) \le f(j_{r-1})$. The optimal answer's jobs don't overlap, so

$$
f(i_{r-1}) \le f(j_{r-1}) \le s(j_r).
$$

So $j_r$ was still compatible with everything greedy had kept when greedy made its $r$th pick. Greedy picks the compatible job that finishes first, so $f(i_r) \le f(j_r)$. $\blacksquare$

Now suppose $m > k$. The lemma gives $f(i_k) \le f(j_k) \le s(j_{k+1})$, so $j_{k+1}$ was compatible with all of greedy's picks and greedy would have kept it. Greedy stopped at $k$, so $m \le k$.

The figure's table is this lemma with numbers in it. Run any losing rule and the table finds a row where $f(i_r) > f(j_r)$. Such a row always exists: if every row held, the argument above would show the losing rule could have kept another job, but the template keeps every compatible job it sees, so its answer can't be extended.

### Exchange argument

The same fact gives a second proof. Take an optimal answer and replace $j_1$ with $i_1$. Since $f(i_1) \le f(j_1) \le s(j_2)$, the result is still compatible and has the same size, so it is still optimal, and it agrees with greedy on the first job. If an optimal answer agrees with greedy on its first $r$ jobs, swapping $j_{r+1}$ for $i_{r+1}$ works the same way, because greedy picked the earliest-finishing job compatible with those $r$. Repeating turns the optimal answer into greedy's one swap at a time without changing its size.

### A certificate you can check

A third proof needs no induction and can be checked by eye. Put a mark at the last instant of each job greedy kept, just before $f(i_r)$. These are the dashed lines in the figure.

- **Every job crosses a mark.** A kept job crosses its own. A skipped job overlapped some kept job $i_r$ that finished no later than it did, since greedy scans by finish time. So it starts before $f(i_r)$ and ends at or after it, which puts the mark at $f(i_r)$ inside it.
- **Disjoint jobs need different marks.** No moment lies inside two disjoint jobs.

So any compatible set has at most $k$ jobs, one per mark, and greedy has $k$. In general the largest set of disjoint intervals is exactly as large as the smallest set of points that hits every interval ([Ben-David et al. 2012](https://2012.cccg.ca/papers/paper69.pdf) derive it from total unimodularity). Earliest finish produces both sets at once.

### Shortest first loses at most half

Shortest first can lose, but never by more than half. Charge every job of an optimal answer to a job greedy kept: a job greedy also kept is charged to itself, and a skipped one to the kept job that blocked it. That blocker was scanned first, so it is no longer than the job charged to it.

Now take a kept job $a$ and an optimal job $b$ charged to it, with $|b| \ge |a|$. If $b$ started after $s(a)$ and ended before $f(a)$, it would be shorter than $a$. So $b$ contains $s(a)$ or the last instant of $a$. The optimal jobs are disjoint, so at most two of them can be charged to $a$, one through each point. Greedy therefore keeps at least half of the optimum, and the three-interval input in the table above shows the bound is tight.

### How badly the wrong rules lose

The experiment runs every rule on random inputs and compares it with earliest finish, which the proof makes the optimum. Starts are uniform on $[0, 1)$. Lengths come from one of three distributions with the same mean: uniform, exponential, or bimodal (80% short and 20% ten times as long). The mean length is set so that about 10 intervals cover a typical moment; the measurement record also has a lighter setting with about 2.

Share of the optimum each rule keeps on 1,000-interval inputs, averaged over 1,000 inputs per row:

| Rule | Uniform | Exponential | Bimodal |
| --- | ---: | ---: | ---: |
| Earliest start | 51.1% | 39.7% | 41.4% |
| Random order | 64.5% | 65.0% | 71.7% |
| Shortest first | 98.5% | 98.9% | 94.3% |
| Fewest conflicts, counted once | 99.2% | 99.6% | 98.1% |
| Fewest conflicts, recounted | 99.96% | 99.98% | 99.72% |

Every 95% confidence interval across the five seeds is within ±0.6 points, too small to print.

What the numbers show:

- **Earliest start is worse than no rule at all.** Scanning in random order keeps 64% to 72%. The intervals earliest start keeps average 1.00 to 1.02 times the mean length, while random order's average 0.44 to 0.61 times. In random order a long interval usually collides with something already kept, so the template quietly favors short ones. Earliest start takes whatever begins next, however long it is.
- **Shortest first and fewest conflicts lose often but by little.** Shortest first lost on 92% to 100% of the 1,000-interval inputs and still kept 94% to 99% of the optimum. On 10-interval inputs it lost on 3% to 13% of them, and its worst loss there was exactly half, the bound proved above.
- **Recounting conflicts helps a lot.** Counting once lost on 60% to 99% of the large inputs, while recounting after each pick lost on 4% to 46%, by under 0.3%. Its worst result on any input was 75% of the optimum, above the proved $2/3$ (see [interval graphs](#weighted-intervals-and-matroids)).
- **Bigger inputs lose more often.** Every wrong rule loses on more inputs as $n$ grows, since a large input contains many small traps.

## Interval Partitioning

Now every interval has to be placed, and the goal is to use the fewest rooms, so that no two intervals in one room overlap. Think of lectures and classrooms. This is the second of the [[reference/cheatsheets/algorithms/intervals|interval problems]].

The greedy algorithm is first fit: take the intervals in some order and put each one in the lowest-numbered room where it overlaps nothing, opening a new room when none fits. Take them by **start time**:

```python
def partition_intervals(intervals):
    """intervals: list of (start, finish). Returns a list of rooms."""
    rooms = []
    for s, f in sorted(intervals):
        for room in rooms:
            if room[-1][1] <= s:
                room.append((s, f))
                break
        else:
            rooms.append([(s, f)])
    return rooms
```

That loop is $O(nd)$ for $d$ rooms. The proof below works for any room that fits, not just the first, so the [Kleinberg–Tardos slides](https://www.cs.princeton.edu/~wayne/kleinberg-tardos/pdf/04GreedyAlgorithmsI.pdf) keep the rooms in a min-heap keyed by when each frees up, and reuse whichever frees up first, for $O(n \log n)$:

```python
import heapq

def count_rooms(intervals):
    free_at = []                                  # one entry per room
    for s, f in sorted(intervals):
        if free_at and free_at[0] <= s:
            heapq.heapreplace(free_at, f)         # reuse the room that frees up first
        else:
            heapq.heappush(free_at, f)            # open a room
    return len(free_at)
```

### Why the order matters

Finish time, the right order for scheduling, is the wrong one here. The smallest input where it loses has four intervals, listed here in finish order:

$$
[0, 1),\; [0, 2),\; [2, 3),\; [1, 4)
$$

First fit puts $[0, 1)$ in room 1 and $[0, 2)$ in room 2. Then $[2, 3)$ fits in room 1 after $[0, 1)$. Last, $[1, 4)$ overlaps $[2, 3)$ in room 1 and $[0, 2)$ in room 2, so it opens room 3. No moment is covered by more than two of the intervals, and two rooms suffice: $[0, 1), [1, 4)$ in one and $[0, 2), [2, 3)$ in the other.

Room 3 was opened because $[1, 4)$ overlapped one interval in each room. Those two blockers, $[2, 3)$ and $[0, 2)$, don't overlap each other, so nothing forces a third room. The proof below needs the blockers to share a moment, and start order is what guarantees it.

Ties need care in examples like this. With $[0, 1), [0, 3), [2, 5), [4, 5)$, first fit in finish order needs three rooms if $[4, 5)$ comes before $[2, 5)$ and two if it comes after, so finish order alone doesn't decide it. The figure and the experiment break every tie by finish time, then start time.

### Proof of correctness

The **depth** of a set of intervals is the largest number that overlap at any one moment. Every valid assignment needs at least depth rooms, since intervals that overlap at one moment need different rooms.

**Claim.** First fit in start order uses exactly depth rooms.

**Proof.** Say it uses $d$ rooms. Room $d$ was opened for some interval $j$ that overlapped an interval in each of rooms $1, \ldots, d-1$. Everything already placed started no later than $s(j)$, so in each room the interval that overlaps $j$ starts at or before $s(j)$ and ends after $s(j)$. Those $d - 1$ intervals and $j$ all contain the moment $s(j)$, so the depth is at least $d$. No assignment uses fewer rooms than the depth, and greedy uses $d$. $\blacksquare$

Both proofs build a witness that bounds every possible answer, marks for scheduling and a crowded moment for partitioning, and then show greedy meets the bound. The Kleinberg–Tardos slides call this a structural bound.

### How many rooms the wrong orders waste

The same random inputs, partitioned by first fit. Start order used exactly the depth on every input, as the proof says. Extra rooms beyond the depth on 1,000-interval inputs, with load 10 (depth about 21):

| Order | Uniform | Exponential | Bimodal |
| --- | ---: | ---: | ---: |
| Finish time | 6.0% | 7.6% | 7.0% |
| Random arrival | 5.2% | 4.2% | 3.2% |

Finish order wasted at least one room on 79% to 87% of these inputs, and at worst used 29% more rooms than needed. It does a little worse than taking the intervals in random order. The smallest losing input has 4 intervals, and the worst observed ratio on 10-interval inputs was 5 rooms where 3 suffice.

> [!note]- Deep dive: arrivals in arbitrary order
> If intervals arrive one at a time in an order you don't control, and each must get its room on arrival, the problem becomes online interval coloring. Rooms are colors, and the depth is the size of the largest clique in the interval graph, written $\omega$.
>
> - First fit is no longer optimal. In the worst case it uses between 5 ([Kierstead, Smith and Trotter 2016](https://www.math.gatech.edu/~trotter/papers/135-First-fit.pdf)) and 8 ([Narayanaswamy and Subhash Babu 2008](https://doi.org/10.1007/s11083-008-9076-6), at most $8\omega - 3$) times as many rooms as the depth. Which number is right has been open for years ([Krekelberg and Liu 2025](https://arxiv.org/abs/2502.06558)).
> - Kierstead and Trotter (1981) gave an online algorithm that never uses more than $3\omega - 2$ rooms and showed no deterministic online algorithm can promise fewer.
>
> Random arrival is far kinder than the worst case. In the experiment, first fit in random order never used more than 1.29 times the depth on a 1,000-interval input.

## Weighted Intervals and Matroids

Give each job a value and ask for the most valuable compatible set, and every greedy rule here fails. One long job worth 10 with two short jobs worth 1 each inside it defeats earliest finish, which takes the two short ones. Make the long job worth 3 and the short ones 2 each, and taking the most valuable job first fails instead. [[algorithms/dynamic-programming#Weighted Interval Scheduling|Weighted interval scheduling]] needs dynamic programming, which still runs in $O(n \log n)$.

Matroids explain why. A family of "independent" sets that is closed under taking subsets is a **matroid** if it also has the exchange property: when $A$ and $B$ are independent and $|A| < |B|$, some element of $B$ can be added to $A$ with the result still independent. The theorem behind most greedy algorithms says that repeatedly adding the heaviest element that keeps the set independent finds a maximum-weight independent set for every choice of nonnegative weights, if and only if the family is a matroid. Rado (1957) proved the "only if" direction, and Gale (1968) and [Edmonds (1971)](https://doi.org/10.1007/BF01584082) the "if" ([Schrijver, Theorem 40.1](https://page.math.tu-berlin.de/~felsner/Lehre/SemMatS/Literatur/Schrijver-40:GreedyAlg.pdf)).

Sets of disjoint intervals are not a matroid. Take $A = \{[0, 10)\}$ and $B = \{[0, 1), [2, 3)\}$: $B$ is larger, but neither of its intervals can join $A$. So by the theorem some weighting defeats heaviest-first, which is the weighted failure above. The unweighted problem escapes because every weight is equal and earliest finish uses the order of the line, which the matroid theorem doesn't see. Kruskal's minimum spanning tree algorithm is the standard example on the other side: the forests of a graph form a matroid, so cheapest edge first is optimal for any edge weights.

> [!note]- Deep dive: interval graphs
> Make each interval a vertex and join two vertices when their intervals overlap. The result is an **interval graph**. Interval scheduling is then maximum independent set, interval partitioning is graph coloring, and the depth is the size of the largest clique. Both problems are NP-hard on general graphs. [Gavril (1972)](https://doi.org/10.1137/0201013) solves both in polynomial time on chordal graphs, which include interval graphs, with greedy algorithms over a special vertex order.
>
> The partitioning proof shows that an interval graph's chromatic number equals its clique number. Every induced subgraph of an interval graph is again an interval graph, so this holds for all of them, which makes interval graphs **perfect**. The certificate for scheduling is the matching statement for independent sets and point covers.
>
> Fewest conflicts is the minimum-degree heuristic for independent set. [Chaplick et al. (2024)](https://arxiv.org/abs/2403.10868) study the version that recounts conflicts after each pick and discards the picked interval's neighbors. They prove it always keeps at least $2/3$ of the optimum on interval graphs, even with the worst tie-breaking, and that $2/3$ is tight. The figure uses the version in the Kleinberg–Tardos slides, which counts conflicts once and then scans. The experiment measures both.

> [!note]- Deep dive: intervals that arrive online
> Suppose jobs arrive in order of start time and each must be accepted or rejected on arrival. If an accepted job may later be dropped, earliest finish survives in online form: keep the current job unless a new one that overlaps it finishes earlier, and swap when it does. [Faigle and Nawijn (1995)](https://doi.org/10.1016/0166-218X(95)00112-5) show this matches the offline optimum on every input.
>
> If accepted jobs can never be dropped, nothing works well. [Bachmann, Halldórsson and Shachnai (2013, Theorem 6)](https://staff.ru.is/mmh/papers/oninter.pdf) show that every online algorithm, randomized ones included, can be forced down to a share of the optimum that shrinks like $1/n$, even when jobs arrive in order of start time. A long job that arrives first is the trap: accept it and many short jobs inside it follow, reject it and none do.
