For a minimization problem, an algorithm is an **$\alpha$-approximation algorithm** if it runs in time polynomial in the size of its input and, on every instance $I$, returns a feasible solution whose cost $ALG(I)$ is at most $\alpha \cdot OPT(I)$, where $OPT(I)$ is the cost of an optimal solution and $\alpha \ge 1$. For a maximization problem the condition is $ALG(I) \ge OPT(I) / \alpha$. The factor $\alpha$ is the **approximation ratio** of the algorithm.

An approximation algorithm may return a suboptimal solution, but its analysis bounds the cost of that solution by a known factor of the optimum on every input, including inputs constructed to make the ratio as large as possible. The definition is of interest chiefly for NP-hard optimization problems, for which no polynomial-time algorithm computes an optimal solution on every input unless P = NP.

Proving such a bound requires comparing $ALG$ with $OPT$, which cannot be computed in polynomial time unless P = NP. The analyses of vertex cover and set cover share a technique for minimization problems: they identify a quantity, computed during the algorithm's execution, that is provably at most $OPT$, and bound $ALG$ against that quantity. For vertex cover the quantity is the size of a maximal matching, and a simple algorithm is a 2-approximation. For set cover it is a sum of prices charged to elements, and the greedy algorithm is within a factor of about $\ln n$. Both factors are tight for their algorithms. For set cover the greedy factor matches the NP-hardness threshold up to lower-order terms, and for vertex cover the factor 2 is optimal if the Unique Games Conjecture holds. Measured against exact optima on random graphs and small real networks, the mean ratios of these algorithms are between 1.00 and 1.84 ([[#Measured ratios]]). The LP relaxation, a third source of lower bounds, is treated in the [[algorithms/linear-programming|linear programming note]].

## The approximation ratio

For a minimization problem, the guarantee of an $\alpha$-approximation is that on every instance $I$

$$
OPT(I) \le ALG(I) \le \alpha \cdot OPT(I),
$$

where $\alpha \ge 1$ may be a constant or a function of the input size. Some authors write the maximization ratio as a number below 1 instead (a "$\tfrac{7}{8}$-approximation" for MAX-3SAT), so figures from different sources are comparable only after the convention is checked.

**The ratio is a worst-case bound.** It constrains the algorithm's output on the hardest input and says little about typical inputs. On the graphs in [[#Measured ratios]], the vertex cover 2-approximation averages between 1.2 and 1.8 times the optimum, and a heuristic with no constant-factor guarantee averages within 5% of the optimum.

**The analysis yields a certificate.** When the analysis compares $ALG$ against a lower bound $L \le OPT$ that the algorithm computes during its execution, $ALG / L$ is an upper bound on the ratio of that particular run, and it can be well below $\alpha$. For vertex cover, $L$ is the size of the matching the algorithm constructs.

> A **PTAS** (polynomial-time approximation scheme) achieves ratio $1 + \varepsilon$ for every fixed $\varepsilon$, in time polynomial in $n$ for each fixed $\varepsilon$ but possibly exponential or worse in $1/\varepsilon$. The hardness results assume P ≠ NP unless the table states otherwise.

## Vertex cover: take both ends of an edge

A **vertex cover** of a graph $G = (V, E)$ is a set $S \subseteq V$ such that every edge has at least one endpoint in $S$. Finding a minimum vertex cover is NP-hard, and its decision version is one of Karp's original 21 NP-complete problems.

**Algorithm.** Initialize $S = \emptyset$ and scan the edges in an arbitrary order. When the scanned edge has neither endpoint in $S$, add both of its endpoints to $S$. After the scan, return $S$.

[Garey and Johnson](https://en.wikipedia.org/wiki/Computers_and_Intractability) credit this algorithm to Gavril; Papadimitriou and Steiglitz credit Gavril and Yannakakis independently. It runs in $O(|V| + |E|)$ time.

The figure applies the algorithm to the marriage network among fifteen Florentine families in the early 1400s, from [Padgett and Ansell (1993)](https://doi.org/10.1086/230190), in which an edge is a marriage tie between two families. The optimum, 8 families, is computed in the browser by exhaustive search over vertex subsets. The scan can be stepped through one edge at a time, and drawing a new random edge order changes the result.

<VertexCoverMatching preset="florentine" />

The size of the returned cover depends on the edge order. Over 1,000 random edge orders of this graph, the algorithm returned 8 vertices twice, 10 vertices 245 times, 12 vertices 598 times and 14 vertices 155 times. The factor-2 bound limits the size to $2 \cdot OPT = 16$.

### Why it is within a factor of 2

Consider the edges whose scan added vertices to $S$, drawn thick in the figure. No two of them share an endpoint, because once an edge's endpoints are in $S$, every later edge incident to them is already covered and adds nothing. These edges therefore form a **matching** $M$. The scan leaves no edge uncovered, so no edge can be added to $M$, and $M$ is a maximal matching.

Every vertex cover, including an optimal one, must contain an endpoint of each edge in $M$, and those endpoints are distinct because the edges of $M$ share none. Hence $OPT \ge |M|$. The algorithm returns exactly two vertices per edge of $M$, so

$$
ALG = 2|M| \le 2 \cdot OPT.
$$

The argument uses $|M|$, a quantity the algorithm computes, in place of $OPT$, so $|M|$ is the certificate described under [[#The approximation ratio]]. On the default run in the figure $|M| = 6$, so the 12-vertex cover is provably within a factor of 2 of optimal without reference to the optimum. Its ratio to the true optimum of 8 is 1.5.

### The factor of 2 is tight

On the complete bipartite graph $K_{3,3}$, every maximal matching covers all six vertices, because after two edges are matched the remaining $a$ and $b$ vertices are joined by an edge that is still uncovered. The algorithm therefore returns all six vertices, while either side of the bipartition, with three vertices, is a cover.

<VertexCoverMatching preset="k33" />

A graph consisting of disjoint edges gives the same ratio more directly, since $|M| = OPT$ and the algorithm takes both endpoints of every edge. No ratio below 2 can therefore be proved for this algorithm, and a ratio below 2 requires a different algorithm. The hardness results in [[#Hardness below a factor of 2]] limit how far below 2 any polynomial-time algorithm can reach.

> [!warning] Taking one endpoint loses the guarantee
> A variant that adds only one endpoint of each uncovered edge has no constant ratio. On a star with $n - 1$ leaves it may select the leaf of every edge and return all $n - 1$ leaves, while the center alone is a cover. Adding both endpoints makes $|S|$ equal to twice the size of a matching, and the matching yields the lower bound on $OPT$.

### The max-degree greedy heuristic

The max-degree greedy heuristic repeatedly adds a vertex of maximum remaining degree to the cover and deletes it together with its incident edges. In the [[#Measured ratios|measurements]] it averaged within 5% of the optimum on every family of graphs and was never more than 13% above it. Its worst-case ratio is nevertheless unbounded, so it is not a constant-factor approximation.

A bipartite construction ([CLRS exercise 35.1-3](https://walkccc.me/CLRS/Chap35/35.1/); the analysis goes back to [Johnson 1974](https://doi.org/10.1016/S0022-0000(74)80044-9)) shows this. Let the left side $L$ have $k$ vertices. For each $i = 2, \ldots, k$, add $\lfloor k/i \rfloor$ right vertices of degree $i$, each joined to its own block of $i$ left vertices, so that each left vertex receives at most one edge from each group and has degree at most $k - 1$. The right vertex of degree $k$ has larger degree than every left vertex, so greedy selects it first. Its removal lowers the degrees of some left vertices, and the same comparison then holds one group down. With ties broken toward the right side, greedy selects every right vertex, about $k(H_k - 1)$ of them, whereas the $k$ left vertices form a cover. On this construction the measured ratio was 1.70 for $k = 10$, 2.30 for $k = 20$, 2.95 for $k = 40$ and 3.60 for $k = 80$, growing like $\ln k$. Breaking ties at random gave the same counts.

The heuristic is the set cover greedy algorithm applied to the sets "edges at vertex $v$", so the set cover analysis bounds its ratio by $H_\Delta$, where $\Delta$ is the maximum degree. The construction shows that the ratio does grow logarithmically.

### Pruning and LP rounding

The matching cover frequently contains vertices that are not needed. A vertex whose neighbours are all in the cover can be removed, since every edge incident to it is covered by its other endpoint. A pass that removes such vertices one at a time preserves a valid cover and never adds a vertex, so the factor-2 guarantee still holds. On the Florentine graph, over the same 1,000 edge orders, the pruned cover had 8 vertices (the optimum) 976 times and 9 vertices 24 times.

<VertexCoverMatching preset="florentine-prune" />

A second 2-approximation, described in the [[algorithms/linear-programming|linear programming note]], solves the LP relaxation and keeps every vertex with $x_v \ge \tfrac{1}{2}$. Its lower bound is the LP optimum, which is at least as large as any matching because, by LP duality, it equals the size of a maximum fractional matching. The rounding step can nonetheless keep many unnecessary vertices. The vertex cover LP has an optimal solution whose values are all $0$, $\tfrac{1}{2}$ or $1$ ([Nemhauser and Trotter 1975](https://doi.org/10.1007/BF01580444)), and on a dense graph that solution can be $\tfrac{1}{2}$ on every vertex, in which case rounding returns every vertex. Every LP solution in the experiment was half-integral, and on random graphs of average degree 4 and above, rounding produced larger covers than the plain matching algorithm.

### Hardness below a factor of 2

No polynomial-time algorithm with ratio $2 - \varepsilon$ for a fixed $\varepsilon > 0$ is known. The best known ratio is $2 - \Theta(1/\sqrt{\log n})$ ([Karakostas 2009](https://doi.org/10.1145/1597036.1597045)), obtained from a semidefinite relaxation. Three hardness results bound the achievable ratio from below.

- [Dinur and Safra (2005)](https://annals.math.princeton.edu/2005/162-1/p08) showed it is NP-hard to approximate within any factor below $10\sqrt 5 - 21 \approx 1.3606$.
- The 2-to-2 Games Theorem of Khot, Minzer and Safra ([final paper](https://annals.math.princeton.edu/2023/198-1/p01), with their STOC 2017 reduction) raised that threshold to any factor below $\sqrt 2$, still assuming only P ≠ NP.
- [Khot and Regev (2008)](https://cs.nyu.edu/~khot/papers/vc_hard.pdf) showed that if the Unique Games Conjecture holds, no polynomial-time algorithm achieves $2 - \varepsilon$. The ratio 2 of the matching algorithm would then be optimal among polynomial-time algorithms up to the additive $\varepsilon$.

## Set cover: the greedy algorithm

**Problem.** Given a universe $U$ of $n$ elements and sets $S_1, \ldots, S_m \subseteq U$ whose union is $U$, choose as few sets as possible whose union is still $U$. Vertex cover is the special case in which the elements are edges and each vertex contributes the set of edges incident to it. Minimum dominating set is another, in which each vertex contributes the set consisting of itself and its neighbours.

**Algorithm.** While some element is uncovered, select the set that covers the most uncovered elements.

Write $k = OPT$ for the size of a smallest cover and $d$ for the size of the largest set. Greedy uses at most $H_d \cdot k$ sets, where $H_d = 1 + \tfrac{1}{2} + \cdots + \tfrac{1}{d} \le \ln d + 1$. Since $d \le n$, this is at most $(\ln n + 1) k$. A shorter argument gives a bound in terms of $n$ alone, and a charging argument gives $H_d$.

### A quick bound: at most ⌈k ln n⌉ sets

Suppose $r$ elements are still uncovered. The $k$ optimal sets cover all of them, so one of those sets covers at least $r/k$ of them, and greedy's choice covers at least as many. Each selection therefore leaves at most a $(1 - \tfrac{1}{k})$ fraction of the elements that were uncovered. After $t \ge 1$ selections the number of uncovered elements is at most

$$
n\left(1 - \frac{1}{k}\right)^t < n \cdot e^{-t/k},
$$

where the strict inequality uses $1 - x < e^{-x}$ for $x \ne 0$. At $t = \lceil k \ln n \rceil$ the right side is at most $n \cdot e^{-\ln n} = 1$, so fewer than one element, and hence no element, remains uncovered. Greedy uses at most $\lceil k \ln n \rceil$ sets.

Both the strict inequality and the ceiling are needed. At $t = k \ln n$ exactly, the right side equals 1 instead of falling below it, and $k \ln n$ is rarely an integer, so the strict inequality and the ceiling together complete the argument. Applying the same argument only until at most $k$ elements remain, and then counting at most one set per remaining element, gives the slightly sharper bound $k \ln(n/k) + k$.

### A sharper bound by charging: H_d

The charging proof bounds greedy against each optimal set separately.

When greedy selects a set that covers $f$ new elements, charge each of those elements $\tfrac{1}{f}$. Each selection distributes a total charge of exactly 1, so the total charge equals the number of sets greedy used.

Now fix one optimal set $S$ and consider the moment at which greedy covers one of its elements while $S$ still has $r$ uncovered elements. Selecting $S$ itself would have covered $r$ new elements, so greedy's choice covers at least $r$, and the element is charged at most $\tfrac{1}{r}$. As the elements of $S$ are covered, $r$ counts down from $|S|$, so the charges on the elements of $S$ sum to at most

$$
\frac{1}{|S|} + \frac{1}{|S| - 1} + \cdots + \frac{1}{1} = H_{|S|} \le H_d.
$$

Every element belongs to some optimal set, so the total charge is at most $k \cdot H_d$, and that total is the number of sets greedy used. In the figure, the number in each square is the charge its element received. The two rows, of 7 elements each, are the optimal sets.

<SetCoverGreedy preset="prices" />

Greedy used 3 sets and the charges sum to 3. The elements of each row were charged 1.50 in total, below the bound $H_7 \approx 2.59$.

Neither bound dominates the other. $H_d \cdot k$ is smaller when every set is small; with sets of at most 3 elements it equals $\tfrac{11}{6} k$. $\lceil k \ln n \rceil$ can be smaller when some set contains nearly all of $U$, since $H_n$ is about $\ln n + 0.58$.

### Worst-case instances for greedy

On some inputs the ratio of greedy grows logarithmically. In the figure, the universe is two rows of $2^m - 1$ columns, and the two rows are an optimal cover. The other sets are column blocks of widths $1, 2, 4, \ldots, 2^{m-1}$, each covering its columns in both rows. The widest block covers $2^m$ elements and each row covers $2^m - 1$, so greedy selects the block. Each subsequent block then covers exactly one more uncovered element than either row, so greedy selects the blocks in decreasing order of width until it holds all $m$ of them.

<SetCoverGreedy preset="two-rows" />

With $n = 2(2^m - 1)$ elements, greedy uses $m \approx \log_2 n$ sets against an optimum of 2, a ratio of about $\tfrac{1}{2}\log_2 n \approx 0.72 \ln n$. This instance is exercise 5.33 in Dasgupta, Papadimitriou and Vazirani's *Algorithms*, and [Mount's lecture notes](https://cs.umd.edu/class/spring2025/cmsc451-0101/Lects/lect07-set-cover.pdf) work through an example. [Slavík (1997)](https://doi.org/10.1006/jagm.1997.0887) determined the worst case, showing that greedy's ratio is $\ln n - \ln \ln n + \Theta(1)$, with upper and lower bounds less than 1.1 apart.

### Weighted set cover

When each set has a cost $c(S)$ and the objective is a cover of minimum total cost, greedy selects the set with the lowest cost per newly covered element and charges each new element that cost per element. The charging proof carries over with $c(S)$ in the numerators. The charges on the elements of an optimal set $S$ sum to at most $c(S) \cdot H_{|S|}$, so the cost of greedy's cover is at most $H_d \cdot OPT$ ([Chvátal 1979](https://doi.org/10.1287/moor.4.3.233)).

With weights the factor is exactly tight. In [Vazirani's example](https://homes.di.unimi.it/cordone/courses/2024-ae/Lez08-Materiali/Vazirani-SCP.pdf), element $i$ of $n$ has its own singleton set of cost $\tfrac{1}{n - i + 1}$, and one set containing every element has cost $1 + \varepsilon$. The least expensive singleton costs $\tfrac{1}{n}$ per element, just below the $\tfrac{1 + \varepsilon}{n}$ per element of the large set, and the same comparison holds after each selection. Greedy selects every singleton, at total cost $H_n$.

### Hardness of approximating set cover

[Feige (1998)](https://doi.org/10.1145/285055.285059) showed that no polynomial-time algorithm approximates set cover within $c \ln n$ for any $c < 1$ unless NP has algorithms running in time $n^{O(\log \log n)}$, and [Dinur and Steurer (2014)](https://arxiv.org/abs/1305.1979) showed that approximation within the same factor is NP-hard. If P ≠ NP, the greedy algorithm from the 1970s is therefore optimal up to lower-order terms among polynomial-time algorithms.

- **Max-degree greedy, which has no constant-factor guarantee, stayed within 13% of optimal on every instance.** Its logarithmic worst case arises on specially constructed graphs such as the bipartite construction in [[#The max-degree greedy heuristic]].

The LP relaxations use HiGHS dual simplex, so each solution is a vertex of the polytope, and every one was checked for half-integrality.
> - **Algorithms.** Matching: edges in a uniformly random order. Pruning: cover vertices in random order, each dropped if all its neighbours are still in the cover. LP rounding: keep $x_v \ge \tfrac{1}{2}$. Max-degree greedy: ties broken at random, or toward the right side for the bad construction. Set cover greedy: ties broken at random.
> - **Instances.** $G(n, p)$ with $p$ chosen for the stated average degree, isolated vertices removed. Barabási-Albert and random geometric graphs from the NetworkX generators. Random set cover instances: each element joins each set independently, and an element left in no set is added to a random one. Seeds 0 to 29 for each family, offset per family; the exact seeds are in the script.
> - **Real graphs.** NetworkX 3.7's bundled copies of the Florentine families marriage network ([Padgett and Ansell 1993](https://doi.org/10.1086/230190); this version has 15 families), Zachary's karate club, the Davis southern women graph (women and the events they attended) and the Les Misérables character co-appearance graph.
> - **Environment.** Python 3.13.18, NumPy 2.5.3, SciPy 1.18.1, NetworkX 3.7, on a 4-core Intel Xeon at 2.30 GHz. The full run takes about 4 minutes, almost all of it in the integer programs for the denser graphs.
> - **The figures** run the same algorithms in the browser with a seeded edge order, and compute their optima by brute force over subsets. Their tests check those optima against the integer program, and the set cover runs against this script's greedy order and costs.

> [!note]- Potentially interesting ideas
> - **How large can the ratio of the pruned matching cover be?** Pruning preserves the factor 2, and its largest measured ratio was 1.29, on the Davis graph. I did not find or construct an instance that pushes it toward 2, and the answer probably depends on the order in which vertices are checked. A pruned cover is a minimal vertex cover, so the question is how large a minimal cover contained in a matching cover can be relative to $OPT$.
> - **Rounding the half-valued vertices more carefully.** Nemhauser and Trotter's theorem also states that some optimal cover agrees with the LP on every vertex the LP sets to 0 or 1, so the difficulty of an instance is concentrated in its half-valued vertices. Running max-degree greedy or the pruned matching on those vertices alone, instead of keeping all of them, might reduce the excess of LP rounding at moderate densities. This was not tested.
